# 下一项决定性实验：信息补齐 × 一个明确执行障碍的解除

设计草案，2026-10-28。**尚未启动，不计入本轮实测结果。**

## 要回答的问题

本轮已出现信息补齐缩小动作差距、以及提高成功率却放大动作差距的完整案例。
CPU 验证表明部分失败有可逆的持物障碍。下一步应检验：同一种执行限制在所有分支共享时，
是否压住了本来存在的信息差；只在某一分支存在时，是否让信息补齐放大该分支的劣势。

这比再扩大分类器、再拟合一批 importance features 更直接地解释三域。

## 最小设计

- 六个机制点：四个原 Dead（s005_t31、s006_t24、s021_t15、s078_t36）与两个原 Fork
  （s010_t29、s073_t10）。来自持物元数据与现有案例，明确作为有目的的机制样本。
- 排除 s007_t25 的原因是手中第一支钢笔属于任务必需物品，不能把释放它解释成同样的无关物品修复。
- 保留原五个候选动作，位置线索有/无 × 执行修复有/无的 2×2 条件。
- 修复策略仅做一个预定义操作：在原动作后，如果正拿着任务目标类别之外的物品，
  执行当前合法的放置动作释放手；该动作占用实际一步预算。随后恢复原 LLM continuation。
- 必须先对全部 30 条分支进行 CPU preflight，明确放置对象、位置、是否触发及反馈，
  固定 cue 的呈现时点与记忆窗口，再锁定协议。不能临时按结果改变修复动作。
- 无修复的两条件可复用本轮每臂前 8 次；新增两条件每臂各 8 次，**480 条新续跑**。
- 不训练。预计约 0.3–0.6 GPU 小时，最多 480×剩余步数的环境动作；
  按六点各自剩余预算计算，最多 12,400 次生成决策（实际修复还会占用一步，成功也会提前终止）。
  当前实验实测吞吐可用于再次校准。固定规模结束，不以显著性决定扩量。

## 读出与判别

主读出保留完整五臂 q、mu、C，以及真实拾取事件；不以标签翻转作唯一证据。

1. **共同障碍：** 修复后出现信息收益或新的动作差异；再补信息使分支接近。
   这支持“当前共同障碍会遮住先前的信息分支”的机制，可能出现 Dead → Fork → 低差异可成功结构。
2. **分支障碍：** 信息单独干预放大差异，加入执行修复后零成功分支被补回、C 下降。
   这支持“信息释放机会后，剩余执行限制成为差异来源”。
3. **局部拾取修复、终局仍不改善：** 后面还有共同障碍；本轮解释仅覆盖一个必要环节，
   不能把它升格为完整成功机制。报告这一边界，不继续无限修复。
4. **有无修复几乎相同：** 当前执行障碍解释不足，优先检查是否错误定位了实际阻断步骤。
5. **只有平均成功率增加、C 无系统变化：** 实用修复成立，但“三域生成/转换”升级故事没有得到支持。

## 能提升到什么程度

若出现上述条件交互，原论文将从“哪些信息源能预测三域”升级为：
同一任务信息与后续执行能力的组合，如何使原候选动作的信用被压住、显现或消失。
它是一个明确的环境机制实验，不是新训练算法，也不假装说明所有 Dead/Fork。

跨环境时复现的对象应是五臂结果结构对两类干预的响应，而不是复制 ALFWorld 的“拿错物品”。
WebShop 可用商品属性信息差与后续选择/购买约束，但需根据真实轨迹定位对应障碍。

## 最重要的边界

强制修复使用环境状态并更改 continuation，是诊断性辅助策略；不能宣称原模型自然学会了它。
该实验不需要与最强 Agent 系统赛跑。贡献取决于条件交互能否解释原三域，
而不是辅助策略的绝对成功率。六点足以决定是否值得继续，不足以估计全环境的普遍发生率。
