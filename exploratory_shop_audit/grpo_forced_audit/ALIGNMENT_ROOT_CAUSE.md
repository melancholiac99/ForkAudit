# 训推差异的控制变量核查

2026-11-17，继续使用 checkpoint2、同一冻结基座和保存的真实输入，不更新参数、不采集购物轨迹、不改变生产训练配置。

结论：对已检查的异常位置，证据支持 **BF16 前向对数值计算路径高度敏感，注意力实现是足以触发动作概率翻转的因素**。这比“温度不同”或“旧权重没有同步”更符合目前证据。尚未把全部差异归结到一个具体CUDA算子的缺陷，也没有证明全部10步训练具有同样程度的影响。

## 最坏位置的控制变量结果

目标位置为 `click[闪银色]` 中的“闪”。下表均针对同一输入和 checkpoint2；root对照在FP32中计算温度缩放和softmax，因此HF基准3.25%与先前原生BF16原地除温度的2.93%略有不同。

| 前向路径 | “闪”的概率 |
|---|---:|
| 保存的实际采样 | 98.64% |
| 新加载同权重的vLLM（单请求、eager） | 91.06% |
| HF BF16 + FlashAttention2，完整序列取该位置 | 3.2519% |
| 同上，仅截至该位置的前缀 | 3.2519% |
| 同上，KV缓存逐token解码 | 3.2519% |
| 同上，LoRA参数临时改成BF16 | 3.2519% |
| HF BF16 + PyTorch SDPA默认后端 | 2.2977% |
| HF BF16 + 强制SDPA数学后端 | 97.2651% |
| HF BF16 + 分块FP32注意力参考 | 1.6188% |
| CPU全FP32，完整序列 | 68.4767% |
| CPU全FP32，仅前缀 | 68.4767% |
| CPU全FP32，KV缓存逐token解码 | 68.4725% |

**不能把97.3%的数学后端当成正确答案。** 全FP32参照为68.5%；两种提高注意力中间精度的实现也不一致，说明局部换后端不足以稳定整个BF16网络。全FP32是更高精度参照，不是精确实数运算的真值。

输出层竞争词的分数已经翻转：FP32中“闪”31.6753、“镜”31.1323；BF16+FA2中“闪”29.375、“镜”31.75。温度0.7将这个分数差转成相反的高置信概率。观察到的是实质分布差异，不能仅用“很小的浮点误差”淡化。

PyTorch官方说明，融合注意力后端可能因浮点计算次序而产生不同结果；SDPA数学后端通常为FP16/BF16输入保留FP32中间计算。这支持本次控制变量设计，但**不能仅凭文档解释本次差异的具体幅度**，本次结论来自实际前向对照。[官方SDPA说明](https://docs.pytorch.org/docs/stable/generated/torch.nn.functional.scaled_dot_product_attention.html)、[数值精度说明](https://docs.pytorch.org/docs/main/notes/numerical_accuracy.html)。

## 其他位置与进一步排除

- 搜索词中的空格：BF16+FA2为32.86%，SDPA默认67.12%，SDPA数学49.99%，全FP32为48.36%。该位置也随注意力路径改变。
- `finish`动作词：BF16+FA2为12.30%，SDPA默认22.27%，全FP32为35.13%；新vLLM约4.58%，历史采样58.83%。不能用一个最坏样本代表所有位置的偏差方向。
- 保持跨层残差为FP32的单位置诊断没有稳定解决问题：FA2仍约3.25%，SDPA默认变成94.57%，数学后端约3.25%，分块参考约95.42%。这一诊断只提高残差流精度，大部分线性运算仍为BF16；不是全FP32前向，也不是可直接部署的修复。
- 同一HF路径的完整序列、仅前缀和逐token解码基本一致；已保存输入与位置编号检查全部通过。只改LoRA参数dtype没有改变被查位置。它们不能解释主要差异。
- 新vLLM重载仍能再现方向相反的大差异，故历史旧权重不是解释该现象的必要条件；这不代替历史每次同步的独立哈希证明。

本轮选取3个已知异常位置做机制定位，非随机总体估计。局部数值路径敏感已被控制变量实验支持；具体从哪层、哪个舍入步骤开始放大仍未逐算子定位。没有据此量化最终训练收益损失。

## 执行和证据

- `alignment_root_cause.py`：GPU BF16后端对照；`--cpu-fp32`为CPU全FP32参照；`--residual-fp32`为单位置残差精度对照。已完成文件拒绝覆盖，部分结果可恢复。
- `analyze_alignment_root.py`：仅用保存JSON重建比较表；精简明细位于 `evidence/alignment_root_20261117/`。
- 原始路径：运行目录 `alignment_diagnostic/checkpoint_0002/root_*.json`，包括全部被测位置、top-5分数和保留的部分结果。
- 普通SDPA数学后端在较长的finish前缀上超过诊断进程20 GiB分配限制，记录为缺失；没有提高上限挤占主审计。另用分块FP32参考完成该位置。未把失败的数学后端结果填为零。
- 诊断开发的首个GPU尝试存在临时dtype转换后恢复精度不完整的问题，已修正为恢复原FP32副本；最终使用 `root_gpu_checked.log` 与续跑结果，初始日志保留且不用作证据。生产模型未受影响。
- CPU全FP32对照耗时549.8秒。GPU诊断共享现有审计阶段的空闲显存，期间主审计持续运行、未出现新的内核故障，设备占用仍按现有记账计算。
- 4项独立注意力参考测试覆盖因果掩码、跨分块、GQA展开、KV缓存偏移和布尔/加性mask；与既有检查合计31项通过。

生产训练仍使用冻结配置。当前结果不支持直接把SDPA数学后端或FP32残差切入训练作为“已修复”；它们未在这些对照中给出稳定一致的结果。后续修复应先通过固定token对照，再决定统一两端计算路径或精度的实现，不改奖励或挑选重采结果。
