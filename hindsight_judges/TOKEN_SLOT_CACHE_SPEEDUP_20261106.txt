Token-slot cache speed optimization, 2026-11-06. User requested accelerating both 7B and 32B.
This supersedes only the model-specific cache scheduling in TOKEN_SLOT_CHUNK_RECOVERY_20261106.txt; all scientific quantities and acceptance thresholds remain fixed.

7B FP32: restore semantic-prefix KV caching, which previously passed its numerical checks. A read-only comparison on deterministic short/median/long real contexts passed all nine original checks (max TV=0.0000138140) and 48 semantic-vs-canonical checks (max TV=0.0000146919). Total measured request time was 4.5617s versus 10.8307s, 2.3743x faster on that microbenchmark. This is not a full-run ETA and did not use target effects or Q values to select configuration. All 7B model parameters must be FP32 to enable this cache policy; applying it to FP16 is rejected.

Memoization: raise per-point full-logprob cache capacity from 256 to 2048 entries, approximately 1.25 GB host memory at this vocabulary size. The old 7B pilot made 31,409 calls for 25,672 unique requests: 18.27% recomputation after eviction. Cache hits return the already computed FP32 vocabulary vector. CPU regression verifies bitwise identical output and fewer forwards. No sampled point, token position, candidate or target is removed.

32B: keep canonical complete-chunk alignment with size 1024. Use four independent batch-one CUDA streams, one for each AF/AM/EF/EM request, with separate KV and memo caches and explicit synchronization/consumer-stream lifetime tracking. The total memo capacity remains 2048 (512 per distribution). No precision, attention or matrix-shape change. The original gate now exercises concurrent requests before comparison to direct scoring. Production-backend numerical validation is saved in run_next_slot_20261106/speedcheck_32b_production before restart. Every original TV<0.005 gate remains mandatory in each formal pilot/full run.

Rejected 32B alternatives (numerical-only read-only diagnostics): 256/128/64 chunks had maximum TV 0.02113/0.01945/0.02805 against the fixed 1024 reference; 512 had maximum TV 0.01976. Restoring semantic caching for all four distributions took 11.364s versus 23.740s but failed with maximum distribution TV 0.01160 and original gate TV 0.00857. Restricting semantic caching to AM alone passed the sampled checks (max TV 0.00427) but saved only 14.8% time and was not adopted. The speedup does not justify switching a partially validated FP16 numerical path when same-arithmetic alternatives exist.

Independent CUDA streams with unchanged batch-one inputs, chunk size, precision and SDPA MATH: 64 real-request comparisons on fixed shortest/median/longest and the known failing point were all bitwise identical. Two workers took 21.775s and four took 20.594s versus sequential 23.835s. Four streams encountered a recovered allocator retry on the longest point (no lost output); peak allocated memory 71,986,835,968 bytes. Same-length batch2 and batch4 passed 128 numerical comparisons (maximum TV 0.00222 and 0.00373) but saved only 3.8% and 3.6% time, respectively. Batching was not adopted. No end-to-end 32B speedup or ETA is claimed from microbenchmarks; formal pilot timings will measure the net benefit.
