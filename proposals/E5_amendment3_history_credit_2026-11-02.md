# E5 修订 3 草案：检索中的历史可学习信用与新增反馈信用

- 日期：2026-11-02
- 状态：**PROPOSED / NOT FROZEN**。基于已经看到的 ALFWorld P8 CPU 和 E4 正式结果设计；不是独立于这些结果的盲预注册。
- 适用对象：E5-S（HotpotQA 开放检索）为主；E5-C 为同题信息在场对照，E5-K 保留原设计。WebShop 仅按修订 2 的回退规则运行。
- 本文是**新增修订草案**，不覆盖 `exploratory_E5/PREREG_E5.md` §1–13，也不改 W-0–W-6、A/K 预测、原功效门和原判定。待确认服务器**未产生任何 E5 pilot/rollout/replay/judge 数据**，并完成纯数据无关测试后，才可归入正式 §14 并单独冻结 commit、记入 DECISIONS；如已有数据，标记为 post-hoc，不得称为 pre-pilot。

## 1. 核心问题与估计对象

检索 Agent 的反事实信用可能混合三种来源：
(1) prompt 中已可见的历史探索结构（重复查询、已见证据、未见过的证据方向）；
(2) 当前动作一步执行后新揭示的证据；
(3) 真实隐藏检索结果和后续运行噪声形成的实例信用。
**历史规则预测与环境反馈规则必须分开评价**，不能因为后者检索到了支撑文档，就把它叫作“历史可识别”。

对每个决策点 i，在固定的 K=5 个草稿候选上定义
`q_ia = mean(reward | fixed state i, force action a, bank 1+2)`（每臂 6 次）
和 `G_u(i; p) = sum_a p_ia q_ia - (1/K) sum_a q_ia`。
p 可为原策略首批合法草稿的加 0.5 平滑分布、同信息条件的历史规则或评判模型选择分布；三者使用相同固定候选集与 q。这个量测量**相对于候选集均匀基线的动作选择收益**，不是超出候选池的全动作最优性，也不是可直接推广的因果训练效果。

**主检验人群 H_prompt**：E5-S 中有 K 个不同有效候选动作、在动作执行前的当前模型 prompt 中**缺至少一篇规范化支撑文章标题**的所有决策点。只依赖已冻结问题元数据与动作前 prompt；**不得**要求任一候选一步检索到支撑文章、Live、Fork、最终成功、奖励差异、模型评判值或者规则是否可用。题目及阶段过滤按 §13 原定义。H_full：完整事实历史中也缺至少一篇支撑文章的敏感性人群。标题出现不等于证据充分，另报告仅标题/段落内容的审计。

按任务聚类 bootstrap 10,000 次、固定种子，所有决策点以任务为单位重抽；报告点数、任务数、可定义率、CI、分任务等权敏感性，原始策略 p 的首批抽样不确定性、候选集质量与 q 的六次续跑噪声敏感性。不得把 CI 跨零称作“证明等效”。

## 2. 检索动作的历史规则：严格避免一步反馈泄漏

历史状态从当前 prompt 可见的查询与检索结果构建；**只用动作前信息**，不使用答案、支撑文档真值、该候选即将返回的文档或未来轨迹。
- 搜索动作 `search(q)`：解析并规范化查询（Unicode NFKC、大小写折叠、空白/标点统一）；精确重复查询为 `repeat_query`。语义近重复另作描述，不能在看结果后调相似度阈值。
- 结果重复 `repeat_evidence`：仅当**历史已经记录的相同查询或可在历史中确定的结果**被复查时才能判定；对从未执行的候选查询，不得通过真实检索返回预判它的结果是重复。文档集合 Jaccard 或语义近重复只作预先锁定的敏感性分析。
- `novel_query`：当前历史未执行过的查询；**不是**“必然发现新证据”。可进一步描述新实体/新关系覆盖：从问题和已见文本抽取的实体槽位（固定解析器，不用答案或支撑标签），候选 query 是否提出未检索的实体/关系组合；解析失败回退到查询新颖性，不臆造新颖证据。
- `answer(a)`：独立类别，不能默认视为“坏动作”。若历史包含足以支持答案的文本证据，可通过事前冻结的、仅历史可见的确定性条件标记 `supported_answer`；若无法可靠判定则 `answer_unknown`，不把错误答案用事后真值倒标为“提前作答”。报告三类的覆盖率及手工盲审一致性。

**R-window**（原信息预算）：先保留可判断的 `supported_answer`；其余默认选 `novel_query`，其次选择非精确重复的搜索，最后保留其余候选，候选内均匀；不能判定时在所有候选上均匀。R-window 仅读取策略实际 prompt 中可见的四步历史，且不访问环境隐状态或答案。
**R-full**：相同规则、相同候选集和回放 q，仅替换为自起点的完整实际历史；只能与同为完整历史的 M 评判者公平比较，与 S 的比较标明额外历史优势。
**R-feedback**（仅作特权观察规则，不可算作历史基线）：一步搜索反馈真正包含动作前缺失的支撑文章时优先；否则回退到 R-window。不能把此臂在模型部署前可用来代替 R-window。

规则排名与并列处理在运行前固定；可见历史存在截断/缺字段时以 `unknown` 处理，不能从原始日志补回 R-window 的信息。冻结解析器、查询正规化函数、证据抽取器与示例测试；不基于 reward/Fork 结果优化启发式。

## 3. 三条检验轴（新结论与旧读法独立）

**E5-H1（主）**：在 H_prompt 上计算原策略均值 `G_u` 与任务聚类 95% CI。CI 上界 < 0：`MISDIRECT-HISTORY`（在固定候选池上相对均匀选取过度集中）；CI 下界 >= 0：`NO-DETECTED-NEGATIVE`；否则 `INCONCLUSIVE`。同时按 Live 归一化报告，不使用任意 −2pp 绝对阈值。

**E5-H2（选样分解）**：在 H_prompt∩Live 上精确报告
`G_u(H∩Live)=w_F*G_u(H∩Live∩Fork)+(1-w_F)*G_u(H∩Live∩nonFork)`；
主检验的总体 G 与仅 Fork 子集 G 必须同表。对 nonFork Live 的补偿项给联合 bootstrap CI；如果下界 > 0 仅说明存在补偿，**不能**单凭此判定已抵消；还要看 H1 的方向、整体加权值与置信区间。Dead 的固定候选 q 相同，贡献理论上为 0；标签误差需报告。

**E5-H3（规则与模型的信息利用）**：配对比较 R-window − policy（同 prompt）、R-full − policy（额外历史，明确不公平的诊断上限）、R-feedback − R-window（新增环境观察），以及可选的 S/M/L/F 评判者与对应规则在**同一 H_prompt 样本、相同候选集、同样 q**上的差异。模型 S 仅原 prompt，M 仅在原 S 上追加完整实际历史，L 和 F 保留原 §13 语义。预设首先报告差值与 CI，CI 下界 > 0 才称“发现规则增益”；不以高于某个后验设定阈值的差距作成功判据。

A2 风格的 `p_best`、Fork 与候选 q 范围的关联仅描述，不进入联合作用读法；禁止将 Fork 条件化后的亏损自动解释成模型错误或“隐藏世界意外”。

## 4. 三环境与原修订的关系

E5-S：H1/H2/H3 用于检验“历史可识别的探索价值”能否在检索迁移；原 W-3..W-6 与 F/L/Fx 判断继续独立报告。E5-C：同题同种子，已给全上下文；只做相同候选池下的历史规则与 F 增益对照，原 A-1/A-2/A-3 不变。E5-K：保持 Sokoban BFS、原 K-0/K-3；不强行把“新查询”概念迁移到规划动作。WebShop：仅依 §13 的原回退。

不将 E4 训练增益当作本修订确认性终点：E5 是信用结构与信息条件验证，任何在 E5 上新开展偏好训练都必须另行预注册。

## 5. 样本与判定纪律

沿用 §13 的正式任务、试点任务、种子、候选生成、银行/评判设定、预设功效门和回退规则；本修订新增分析不因效果不明显改变样本量。H_prompt 可定义点数、Live、Fork、非 Fork 及每环境覆盖率全部报告；稀有类别仅作描述。主检验 H1 不因 Fork 数量不足而删除，但若任务聚类/置信区间不足以识别符号，结论为不确定。不得把对 P8/E4 已知方向的选择写成盲发现。

**试点边界**：试点继续只用于验证接口、确定性、基础成功率、Live 比例和预先登记的规模门；不得在试点读取 H1/H2/H3 的奖励差、规则优劣、Fork 标签分层收益或评判结果后改规则。试点前需独立核对：E5 服务器无任何试点/正式 rollout、回放、评判、标签输出；冻结实现哈希、所用模型/后端版本、完整数据依赖及 DECISIONS，产生不可变的试点前修订 commit。

## 6. 数据无关的 preflight 与合成自测（现在可以执行）

1. 用合成历史（有四步截断与完整历史）测试 R-window 完全不能看到旧查询，R-full 能看到；重复查询正规化、搜索/回答混合、空动作、缺损 prompt、并列回退。
2. 注入“同查询但不同未来检索结果”孪生世界：R-window 输出完全一致；R-feedback 可以不同，验证历史/环境信息严格隔离。
3. 合成 q 与 Fork/Dead/Live 标签测试 H1 均值、H2 加权恒等式、H3 配对差及按任务聚类重抽；同时构造 Fork 内负、nonFork 正补偿，以及总体负、正、零三种情形。
4. 测试 H_prompt 标签与决策前 prompt/支撑标题元数据相关，但与任何一步返回、奖励和 Fork 标签无关；H_full 不使用未发生的动作。
5. 独立检验 R-window 的输入来源与 S prompt 字节一致，R-full 与 M 的历史来源一致；核对搜索模板中的历史长度实际为**四步**（不是 ALFWorld 两步）。
6. 真实数据的 preflight 只验证环境安装、路径、版本、结构与预期缺失字段；任何真实 reward/评判输出须等冻结后才读取。异常即停，不静默放宽数值门。
