## 1. 核心问题与估计对象

检索 Agent 的反事实信用可能混合三种来源：
(1) prompt 中已可见的历史探索结构（重复查询、已见证据、未见过的证据方向）；
(2) 当前动作一步执行后新揭示的证据；
(3) 真实隐藏检索结果和后续运行噪声形成的实例信用。
**历史规则预测与环境反馈规则必须分开评价**，不能因为后者检索到了支撑文档，就把它叫作“历史可识别”。

对每个决策点 i，在固定的 K=5 个草稿候选上定义
`q_ia = mean(reward | fixed state i, force action a, bank 1+2)`（每臂 6 次）
和 `G_u(i; p) = sum_a p_ia q_ia - (1/K) sum_a q_ia`。
p 可为原策略首批合法草稿的加 0.5 平滑分布、同信息条件的历史规则或评判模型选择分布；三者使用相同固定候选集与 q。这个量测量**相对于候选集均匀基线的动作选择收益**，不是超出候选池的全动作最优性，也不是可直接推广的因果训练效果。

**E5-S 的主检验人群 H_prompt**：有 K=5 个不同有效候选动作、在动作执行前的当前模型 prompt 中**缺至少一篇规范化支撑文章标题**的所有决策点。只依赖已冻结问题元数据与动作前 prompt；**不得**要求任一候选一步检索到支撑文章、Live、Fork、最终成功、奖励差异、模型评判值或者规则是否可用。题目及阶段过滤按 §13 原定义。H_full：完整事实历史中也缺至少一篇支撑文章的敏感性人群。标题出现不等于证据充分，另报告仅标题/段落内容的审计。

**E5-C 的 H_prompt 按设计为空，不得直接套用 S 的 H_prompt 检验。** E5-C 的新审计人群固定为 C_all：全部有 K=5 个不同有效候选、两库 q 完整的决策点（不按 Fork / 回放结局 / 评判者筛选）；C_pre：C_all 中 t∈{1,2,3} 的决策点；C_final：t=4 的决策点。E5-C 另做操纵检查：在其全部动作前 prompt 中，十篇上下文包含的两篇支撑文章标题均可被文档标题解析器识别。检查若失败，报告格式/环境异常，不把 C 解释为信息已在场的有效对照。**C_all / C_pre 不以支持文章是否缺失作为入选条件。**

E5-S 与 E5-C 使用同样的历史规则，但各自轨迹与候选池可以不同；跨环境效应按共同问题 ID 配对，不假装逐决策状态相同。E5-H1/H2 保持 S 的 H_prompt，规则效应跨环境的正式对照限前 3 步；第 4 步另列（见 §2、§3）。

按任务聚类 bootstrap 10,000 次、固定种子，所有决策点以任务为单位重抽；报告点数、任务数、可定义率、CI、分任务等权敏感性，原始策略 p 的首批抽样不确定性、候选集质量与 q 的六次续跑噪声敏感性。不得把 CI 跨零称作“证明等效”。

## 2. 检索动作的历史规则：步数预算 × 实体级新颖性，严格避免一步反馈泄漏

**先尊重环境的 4 步硬预算。** 源码中的 Search Game 在第 4 次动作后无条件终止；若第 4 步执行搜索，无法随后作答，最终奖励为 0（原 §13.2）。当前 prompt 的历史步数（第 1 步无历史，后续含已执行步数）可见，属于动作前信息。R-window、R-full、R-feedback 都必须遵守以下规则，绝不把四步之外的结果作为其输入。

**第 4 步（t=4）**：只能在固定候选池内的有效作答臂（answer）之间均匀选取；不得给搜索臂任何概率，不根据答案真值决定选哪个作答臂。**如果候选池里没有作答臂，标记 RULE_UNAVAILABLE_NO_ANSWER_ARM；不额外生成动作、不修改五臂候选池、不伪装成一个合法作答策略。** 原 policy 的 H1/H2 和 q 仍然按原五臂计算；规则对照的该点单列不可用与覆盖率，不进入 R−policy 的均值。若原 §13 的五臂生成流程导致大量无作答候选，按预先声明的不足覆盖规则报告，不偷偷换候选构造。

**第 1–3 步（t=1,2,3）**：主规则使用“**实体级新颖性**”，而非原草案字符串未出现的 novel_query。仅使用当前 prompt 可见的先前查询和返回文档标题（R-window），或截至 t−1 的完整真实历史（R-full），以及固定候选动作，不访问候选的一步返回、真实支撑标题/答案标签、奖励、未来或隐状态。

- **先解析环境动作**：search(q) 和 answer(a) 两类，规范化查询采用 Unicode NFKC、大小写折叠、空白与标点规整；原始查询字符串是否相同只用来排除已执行过的精确重复查询（不再作为新颖性主定义）。尤其不能把提示模板的示例 search 标签误当成实际执行的查询；只读取有 Step n: 前缀的真实历史记录。
- **提取已见文档标题**：复用 §13 检索文档的格式，解析动作前 prompt 中 <information> 的 Doc n 标题；E5-C 初始给定的十篇文档标题也必须算“已见”，绝不能忽略。R-full 再补截至 t−1 的历史检索返回，R-window 严格停留在 prompt 截断窗口内。标题规范化后用明确的 token 边界判断，不允许自由语义检索、答案或支撑标签作为辅助。
- **从候选查询抽取实体**：按冻结在试点前的确定性解析器提取带引号的实体短语、专有名词连续片段、首字母缩略词，以及问题原文可识别而在查询中被大小写改写的实体短语；最长匹配、重叠/通用疑问词与停用词的处理都以同一代码和合成自测冻结。**不从未来检索结果、gold supporting_titles 或最终答案建立实体词表。** 若解析不可靠，标记 entity_unknown，不回退为 novel_query。
- **实体新颖**：候选搜索不是精确重复查询，至少有一个可靠解析出的实体**没有作为完整 token 序列出现在任何动作前已见文档标题中**，则为 novel_entity。若所有可靠实体都已在标题中出现，记为 seen_entity；没有可靠实体则 unknown。词形/别名的语义扩展不在主规则中。
- **R-window 与 R-full 的选择分布完全一致**：t≤3 时只要至少有一个 novel_entity 搜索臂，就对这些搜索臂均匀分配全部概率；如果没有，则**在原五臂候选上均匀回退 R0**。作答臂不自动认为坏动作；没有 supported_answer 解析器，也不能利用答案真值选作答臂。候选中多个 novel_entity 并列时固定均匀，不根据 q 优化排名。

**R-window** 只能读当前模型 prompt、可见的 4 条最近历史及固定候选；**R-full** 使用同样判别器和回退，但可以读截至 t−1 的全部 factual 历史，因此对应 M 评判者的信息预算。对 R-full−policy 的结果继续标为“额外历史诊断”，不伪装为与原 policy 同输入。

**R-feedback** 是额外环境信息的诊断规则：t≤3 时，只有候选执行一步后真实检索到在动作前缺失的支撑文章才优先该臂，否则回退 R-window；t=4 必须与上面的 answer-only 约束相同，**不能在最后一步使用搜索 peek 提高选臂收益**。它不属于仅历史可用的信息。

**诊断而非主规则的特征**：精确字符串新颖性 novel_query、语义近重复、返回文档集合相似度、答案是否有足够证据、文档标题中包含实体的匹配方式；可以描述但不得在看到真实效果后改为主规则。原草案 supported_answer 作为主规则的可选项**正式从本版方案移除**。

规则解析器与示例测试在试点前冻结；所有未解析、无作答臂、回退均报告数量与任务覆盖。不得因 R-window 的表现不佳改用 R-full、支持答案判断或字符串新颖性。

## 3. 四条检验轴：S 的原 H_prompt、C 的新 C_all，以及可否证的环境内差异

**E5-H1（E5-S 主人群）**：在 S 的 H_prompt 上计算原策略均值 G_u 与任务聚类 95% CI。CI 上界 < 0：MISDIRECT-HISTORY；CI 下界 ≥ 0：NO-DETECTED-NEGATIVE；否则 INCONCLUSIVE。同时按 Live 归一化报告，不使用任意 −2 pp 绝对阈值。E5-C 不进行此 H_prompt 检验，因为人群为空。

**E5-H2（E5-S 的选样分解）**：在 S 的 H_prompt∩Live 上精确报告
G_u(H∩Live)=w_F G_u(H∩Live∩Fork)+(1−w_F)G_u(H∩Live∩nonFork)。
总体与 Fork 子集的 G_u 必须同表；nonFork Live 的补偿项给联合 bootstrap CI。补偿 CI 下界 >0 也不等于整体已经抵消；还必须看 H1 及完整加权和。Dead 值相同则 G_u=0；标签误差需报告。

**E5-H3（S 内历史规则的增益）**：在同一固定候选池和 q 上报告 R-window − policy（同 prompt）、R-full − policy（额外历史，非公平部署对照）、R-feedback − R-window（新增观察），及可选 S/M/L/F 评判者的匹配预算比较。H_prompt 全部可定义点用于 H1/H2，**R 的可评估子集必须明确标记**：前 3 步均可按规则计算；最后一步仅在至少有作答候选时可评估。所有对照同时报告覆盖率与 t≤3 主机制层，不得因为排除了无作答候选改变 H1/H2 人群。CI 下界 >0 才称规则显著改善，而非“未显著为负”。

**E5-H4（新增的 E5-S / E5-C 环境内对照）**：同一条冻结的 **R-window** 规则及相同 q/G_u 定义用于两个环境，但审计人群不同：

- S：H_prompt∩{t≤3}，并列报告 S 全部可定义前 3 步作为无缺失标题条件的敏感性。
- C：**C_pre=C_all∩{t≤3}**；C_all 包含 C 的所有可定义点，不采用 H_prompt 或 Fork 条件筛选。C_final 的第 4 步另表，避免 answer-only 预算规则制造机械的跨环境差异。
- 对每个环境，预先定义 Δ_env = G_u(R-window,q) − G_u(policy,q)，即在固定候选五臂中相对原策略的规则选择收益，既不是总任务成功率，也不是训练收益。C 的原 A-1/A-2、C-0 与 A-3 仍以 §13 的原人群/规则**独立**计算，不被本 H4 替代。
- **三项联合预测**：S 的 Δ_S 95% CI 下界 >0；C 的 Δ_C 95% CI 上界 ≤0（严格的非正方向标准；CI 跨零只能叫 INCONCLUSIVE）；同时 [Δ_S−Δ_C] 的任务配对 95% CI 下界 >0。按**共同问题 ID**分组联合 bootstrap 10,000 次、固定种子；只有两环境都含合格前 3 步决策点的问题进入配对交互，分别报告覆盖量。两环境的具体轨迹和候选池不同，**不称之为同一个决策状态的因果干预**。
- 读法独立于既有 E5 注册读法：三项均满足且试点规则覆盖门通过为 H4-DISSOCIATION；S 为正但 C/交互不满足为 H4-PARTIAL；C 明确为正或 S 明确非正为 H4-COUNTER；任一关键 CI/覆盖不足为 H4-INCONCLUSIVE 或 H4-RULE-UNAVAILABLE。不能把“C 不显著为正”写成“C 已证实非正”。

A2 风格的最优臂偏好、Fork 与候选 q 范围的相关性只报告描述，不进入 H1–H4 的联合判定。避免把 S 的 Fork 条件负收益解释成世界 surprise 的直接证据。

## 4. 三环境与原修订的关系

**E5-S（开放检索）**：以 H_prompt 进行 H1/H2、H3；在 t≤3 检验实体新颖性历史规则增益，和 E5-C 构成 H4。原 W-0..W-6、原 §13 的 F/L/Fx、I/U/Fork 判定继续独立报告，不因 H4 成败重新定义。

**E5-C（同问题、完整上下文）**：**H_prompt 为空集是预期结果**，不把其强行计算成零或选另一个缺失标题人群。新增审计人群 C_all，主要 H4 比较采用 C_pre。两篇支撑文章已在 prompt 内的条件用元数据操纵检查确认，但**历史规则本身不读取支撑文章身份**。预测同一 R-window 在 S 有正向规则增益、在 C 不为正，原因是已提供十篇上下文时“进一步搜新实体”未必有用。这是新的预注册前假说，不是部分可观察理论的数学必然结论。原 A-1/A-2、A-3、C-0 与已有缺失环境读法全部保留。

**E5-K（Sokoban）**：保持原 BFS 规则、K-0/K-3，不强行迁移实体检索规则。**WebShop** 仅按原 §13 的回退运行。E5 仍是信息/信用结构检验，不把 E4 训练增益当作其确认性终点；任何新偏好训练均须另行预注册。

## 5. 样本、试点规则覆盖门与判定纪律

沿用 §13 已冻结的正式任务/试点任务、种子、候选生成、银行、评判、样本规模、功效门及回退规则。本修订不得根据新规则效果好坏增减样本量。E5-S 的 H_prompt 与 E5-C 的 C_all/C_pre 各自报告可定义点数、任务数、t=1..4 分布、Live/Fork/非 Fork、缺失与最终作答候选比例，低频层只描述。

**新增纯动作前“覆盖率门”**（草案建议阈值必须在服务器 pilot 前经合作者确认并固定）：

- **C_all_rule**：E5-S 试点中 t≤3 且五臂完整的决策点内，R-window 规则分布与固定五臂均匀分布的总变差 TV>0 的点比例；**建议最低 15%**。第 4 步一律剔出分母，避免“只在作答臂中选择”机械抬高覆盖率。只依赖 prompt、候选及实体解析器。
- **C_within_search**：E5-S 试点中 t=2/3、至少两个有效搜索候选的点，规则是否在**搜索候选之间**产生非均匀偏好（有 novel_entity 搜索臂、也有非 novel_entity 搜索臂）；**建议最低 5%**，并报告分母及至少 20 个可评价点。这个门防止规则实际只会“有搜索就选搜索”，而不能区别实体搜索的方向。E5-C 同样报告上述两项和实体提取成功率，但不要求 C 达到正覆盖门（正是要检验信息在场时规则价值是否消失）。
- 若任一 E5-S 覆盖门失败，**仅 H3/H4 的规则机制主张标记 RULE-UNAVAILABLE / COVERAGE-FAILED**，不得把它算成规则收益为零，也不得根据奖励换回 novel_query 或 supported_answer；原 §13 的试点、W/A/K 注册实验可按自身门继续执行。规则的 TV、解析覆盖率、作答臂缺失率均在看任何 H1/H2/H3/H4 收益前登记并报告。
- 由于这两个数值是当前 v2 方案中**先行提出、尚待冻结**的阈值，不能把它们说成已通过试点或服务器验证。

**试点边界**：试点仅使用原 §13 允许的接口、确定性、基础成功率、Live 比例、规模门，再加上述**只读历史与候选**的规则覆盖门。**不得**在试点看 H1/H2/H3/H4 奖励差、规则增益、Fork 分层收益或评判结果后修改解析器、阈值或人群。pilot 前独立查明 E5 服务器没有正式试点/rollout/replay/judge 数据，冻结完整实现和输入哈希、模型/后端版本、依赖与 DECISIONS；若事实上已有数据，修订 3 只能按实际时间标记 post-hoc。

## 6. 数据无关的 preflight 与合成自测（可在冻结前做）

1. **硬预算**：构造 t=1/2/3/4 的候选池，检验 t=4 时只在 answer 臂中均匀分配；没有 answer 臂时明确标记不可用；在 t≤3 保持候选数和 R0 回退；环境源码 Search Game 对第 4 步搜索的结局为 0。
2. **实体而非字符串**：同一实体的查询改写（例如“Who directed Blade Runner?” 与 “Blade Runner director”）须判为同一实体新颖状态；若该实体标题已在先前文档中出现，两种查询均不能当作新实体。测试大小写、NFKC、引号、多实体、标题部分 token 匹配、重复查询、无可靠实体 unknown、模板示例标签不被误作真实查询；**unknown 不回退到字符串 novel_query**。
3. **输入隔离**：同查询/同历史但未来检索结果不同的孪生世界中，R-window 与 R-full 输出完全相同（只给相同的动作前历史时）；R-feedback 可不同。R-window 只能看到四步 prompt 里实际有的历史，R-full 才能读取完整事实历史。
4. **E5-C 有据可验**：同一个 HotpotQA 问题构造 S 只有题目、C 另有十篇文档标题的初始 prompt；解析出 C 的两篇支撑标题都已在上下文中；H_prompt 在 C 为空，C_all/C_pre 正常有点。不以元数据支撑标题向 R 规则提供特权输入。
5. **统计与配对**：合成 q/标签检查 H1 平均收益、H2 Live/Fork 分解恒等式、H3 成对增益；用同问题的两个不同动作轨迹检查 H4 的联合任务 bootstrap，且不按逐决策索引硬配对。覆盖门只从 prompt/候选产生，不读 q/reward/Fork。
6. **真实服务器 preflight**：只校验文件、环境安装、检索接口、模型 revision、解析器与候选/标题字段、预期缺失，不访问正式奖励；实际样本前先取得零 pilot 证据。任何格式异常即停，不临时放宽规则或 gate。

实体解析器必须给出**固定源代码、正则/停用词、版本和 SHA256**，在真实 pilot 前以合成例子测试通过。此草案提供的解析器是参考实现，尚未登记为预注册完成。
