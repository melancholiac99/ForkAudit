# 提案 P7：第二环境的选择标准与试点协议

- **状态：ADOPTED（2026-10-31），落实为 `exploratory_E5/PREREG_E5.md` 第 13 节（修订 2）。** 登记：DECISIONS D-061。
- **来源：** 研究者担心 WebShop 本身不适合这个机制、结论不显著，希望结论更强；并转来一份候选第二环境清单（ScienceWorld、WebArena、SWE-bench Verified、WorkArena、HotpotQA、TabFact、DROP）。
- **作用：** 说明为什么选"检索 Agent（预测存在）+ 同题给全上下文（环境内对照）+ Sokoban（跨环境对照）"，以及以后再加环境时按什么标准、走什么试点流程。

---

## 1. 核心判断：第二环境要能"预测缺失"，不只是"再复现一次"

论文的核心主张是：一步反馈的价值来自它补上了 prompt 里缺的决定性事实；能力只在事实在场时起作用。只在一个新环境上复现，最多说明"又看到一次"。要说明效应**只**出现在信息受限的分叉上，需要事先预测"哪里没有效应"并检验：

- **存在：** 决定性事实必须靠动作获取的环境（检索）；
- **环境内缺失：** 同一环境、同一 Agent，把事实直接放进上下文；
- **跨环境缺失：** 完全可观察、难点在计算的环境（Sokoban）。

这样，同一套测量在三处给出"有 / 无 / 无"，且有与无之间的差显著（A-3、K-3），结论才是双重分离。

## 2. 选择标准

| # | 标准 | 原因 |
|---|---|---|
| C1 | 状态可以通过重放动作前缀精确恢复，且便宜 | M0 协议每点需要约 90 次续跑；不能精确恢复就没有回放真值 |
| C2 | 决定性事实能**事前、程序化**地定义（用于 I / U 分层），且不依赖结局 | 分层是检验的核心；靠人工或事后标注会引入自由度 |
| C3 | 7B 的成功率在可测范围（约 0.15–0.85） | 太低则几乎全是 Dead 点，太高则没有分叉 |
| C4 | 存在足够多的 Live 分叉，并且两层（I、U）都有 | 功效门要求每层 ≥ 40 个有评判分数的 Fork |
| C5 | 有现成、公开的 Agent 接口（模板、动作投影、成功判据） | 可比性；避免"我们自己搭的环境"这一质疑 |
| C6 | 事先能说出效应应该存在还是缺失 | 只有这样才能做预测缺失的对照 |
| C7 | 续跑成本可接受（短回合、确定性、无外部网络） | 单卡完成 |

## 4. 试点协议（通用）

1. **冻结试点集**：与正式集不重叠的少量任务（50 个），单独提交。
2. **只跑**：rollout、库 1、库 2、一步返回、Live 标签、分层。**不读** Fork 标签与任何评判输出。
3. **通过条件**：成功率在 [0.15, 0.85]；Live ≥ 可定义点的 25%；重放分歧为 0 且实际臂一步返回 100% 一致；按正式集规模外推，预测存在的环境 Live I 与 Live U 各 ≥ 150，预测缺失的环境 Live ≥ 300。
4. **不通过时的处理事先写定**（PREREG_E5 §13.4–13.5）：只缺数量就按规则扩大正式集一次；成功率不在范围内就换难度级（Sokoban 阶梯）或放弃该环境；一律先写 DECISIONS 再执行。
5. 试点数据不进入任何分析。

## 5. 这个设计的风险

- **E5-S 的分层代理：** 标题在场不等于支撑句在场（wiki-18 按百字分段）；问题也可能靠参数知识答对。两者都使 I / U 的区分变模糊，方向上倾向于削弱效应，而非制造效应。
- **臂的构成：** 检索环境中不同查询可能检索到相同文档；E5-C 中答案臂可能更多。A-3 的差异若伴随臂构成变化，需在正文说明（已登记为描述项）。
- **Sokoban 的 A-1：** 一步反馈展示的是下一步棋盘，32B 本可自己推出来，但未必推得对。若 A-1 在 Sokoban 不成立，说明反馈也在"替评判者计算"，论文必须收窄"信息"的表述（§13.6 已写明）。这正是把 Sokoban 放进来的意义。
- **检索服务资源：** Flat 索引约 65 GB（FP16 上 GPU 约 32 GB），与 vLLM 共卡需要调显存比例。

## 6. 以后再加环境

按第 2 节七条标准逐条写出判断，事先写明预测存在还是缺失，过第 4 节的试点门，然后才写确认性预注册。优先补"预测存在"的第二个实例（例如另一种需要检索事实的环境），而不是再加一个与 ALFWorld 机制相同的环境。
