# 数学 OPSD 实验方案 · Qwen3-1.7B

2026-11-24 · 探索性复现 · 两个训练组，共用一个未训练基座 · 每组一个训练种子

## 1　研究问题

先复现官方 1.7B 数学 OPSD（R），再问一个直接影响是否值得做投影的问题：**在老师开启 thinking、学生训练时关闭 thinking 的同一配方下，给老师看本题参考解答，能给最终学生增加多少准确率？**

主要比较是第 100 步的 R − T0。R − B 衡量本机复现出的总收益，T0 − B 衡量老师只看题目时仍能得到多少收益。三组评测时都只看题目，都开启 thinking。本轮只训练 R 和 T0。

| 组 | 训练时老师看到什么 | 学生做什么 |
| --- | --- | --- |
| B | 无训练 | 直接评测原始 Qwen3-1.7B |
| R | 题目、该题参考解答、官方过渡指令 | 自行采样回答，在自己的回答前缀上学老师的下一 token 分布 |
| T0 | 题目、通用作答指令 | 沿用 R 的学生提示、采样和损失，在自己的回答前缀上学老师 |

**T0 唯一的训练改动在老师提示。** 在 collator 里，R 保留官方分支。T0 将老师的 user message 设成以下文本，仍通过老师的聊天模板渲染，`enable_thinking=True`。学生两组都沿用官方模板，`enable_thinking=False`。T0 同时移除参考解答正文、起止标记以及要求阅读解答的过渡段。[官方提示构造](https://github.com/siyan-zhao/OPSD/blob/ae7d2519e94920c4eb6206c0c26de46d9c50abae/data_collator.py)

```text

```

**共同配方。** 两组从同一基座开始，用同一训练种子、数据顺序和优化器配置。每组独立生成 on-policy 回答。老师在学生采样出的同一段 token 上打分，打分时关闭 LoRA（`--fixed_teacher`），从始至终使用初始模型。

| 设置 | 冻结值 |
| --- | --- |
| 训练规模 | 每组 4 卡，每卡 batch 4，梯度累积 2，有效 batch 32 |
| LoRA 与优化 | rank 64，alpha 128，官方七个线性模块，学习率 5e-6，梯度范数上限 0.1 |
| 学生采样 | 温度 1.1，top-p 0.95，top-k 20，最多生成 1,024 个 token |
| 蒸馏 | 全词表前向 KL，方向为老师到学生，温度 1.1；沿用官方实现，先将各词表元素的 KL 贡献截到上限 0.05，再归约 |
| 检查点 | 第 25、50、75、100 次优化器更新时保存。@100 为主比较，@50 看趋势 |

保留官方 30 epoch 配置及其学习率日程，用共同的停止回调在保存 @100 后结束。直接缩短调度器的总步数可能改变前 100 步的学习率轨迹。[损失实现](https://github.com/siyan-zhao/OPSD/blob/ae7d2519e94920c4eb6206c0c26de46d9c50abae/opsd_trainer.py)

**启动时核对一题即可。** 用同一题渲染两个组的提示。换掉该题的参考解答，R 的老师输入应改变，T0 的老师输入和两组的学生输入应逐 token 不变。用同一段测试回答检查两组实际参与损失的回答 token 对齐。保留这次核对的记录，随后直接开训。

## 3　先看第一份结果，再补全正式评测

1. **训练。** 有 4 张卡就顺序跑 R、T0，各用满 4 卡；有 8 张同型号卡可分两组并行，使用独立端口和输出目录。记录模型加载时间、前 10 步和全程训练耗时。
2. **快报。** 在 AIME24 上先评 B、R@100、T0@100，均用种子 1001、每题 12 次采样。每个模型 360 条回答。三项完成即报准确率、R − B、R − T0 和实际耗时。快报计入最终汇总，后续直接复用。
3. **正式评测。** 对 B、R@50、R@100、T0@50、T0@100，分别评 AIME24、AIME25、HMMT February 2025。每套 30 题，每题每个种子采样 12 次；四个解码种子固定为 1001、2002、1500、4004。完整矩阵共 21,600 条回答，含快报的 1,080 条。三个基准逐项报告，主要汇总取三者等权平均。第三个种子 1500 沿用 OP²SD 作者公开评测脚本中的四种子组合。[四种子原始设置](https://github.com/MBZUAI-reasoninglab/OP2SD/blob/dee6efb2169dfff9b068ea8cda6268182af22a2b/scripts/evaluate.sh#L15)

**按耗时缩减。** AIME24 快报共 1,080 条回答。三个模型各使用 4 张同型卡，从各自评测进程启动计至 360 条回答判分并写盘，累计三段墙钟时间，包含模型加载。下载和排队另计。累计时间 **超过 90 分钟**时，R@50 和 T0@50 在全部三个基准只评种子 1001，B、R@100 和 T0@100 仍评全部四个种子，总量降为 15,120 条。等于或低于 90 分钟时执行完整矩阵。只按耗时选定一次，快报的准确率不参与选择。

**评测实现。** 沿用官方 `eval/evaluate_math.py` 的提示和答案判定，thinking 开启，温度 1.0，最多生成 38,912 个新 token。官方 README 和固定提交的脚本对 top-p 有一处差异：README 写 none，脚本实际在 thinking 下将缺省值设为 0.95。本次以运行脚本为复现对象，三组统一显式设 `top_p=0.95`、`top_k=-1`、`min_p=0`、`presence_penalty=0`，把生效值写进报告。该版本评测入口没有解码种子参数，补一个 `--seed`，传入 vLLM 的 `SamplingParams`；每个“组／步数／基准／种子”用独立输出文件。确认评测日志实际载入对应 LoRA，再记为检查点成绩。[官方评测代码](https://github.com/siyan-zhao/OPSD/blob/ae7d2519e94920c4eb6206c0c26de46d9c50abae/eval/evaluate_math.py) · [README 的设置及结果](https://github.com/siyan-zhao/OPSD/blob/ae7d2519e94920c4eb6206c0c26de46d9c50abae/README.md)

## 4　怎样算分，怎样决定要不要做 P

**Avg@12** 是每题 12 次回答中答对的比例，再对题取平均。四个种子分别算分，报告四种子均值。对 R − T0、R − B、T0 − B，先在相同基准和种子内作差，再报告均值和标准误（四个配对差值的样本标准差除以 2）。宏平均也先在每个种子内计算。这个标准误描述固定试题上的解码波动；每组只训练了一次，训练种子间的变化仍未知。若触发 §3 缩减，@50 趋势比较各组均取种子 1001，四种子标准误记为不适用。并列报告平均生成 token 数和达到长度上限的比例。

**判定区间。** 在 @100 主比较中，先对每题、每组的 4 个种子 × 12 次采样取平均，得到每题 48 条回答的准确率。对 R − T0、R − B、T0 − B 按同题配对。将 90 题按三个基准分层，每次在每个基准的 30 题中有放回抽取 30 题，三组与三个差值共用抽到的题目。先算各基准平均差，再将三个基准等权平均。以种子 20261124 重抽 10,000 次，取第 2.5 与 97.5 百分位数作为 95% 判定区间。四种子标准误另列，用于描述固定题目上的解码波动。

下表中，L 和 U 是相应宏平均配对差的区间下界和上界，单位均为百分点。L > 0 为明确为正，U < 0 为明确为负。区间完全落在 [−2, +2] 内（含端点）为差值小且估计足够精确。其余记为不确定。方向和幅度分别报告；例如 [+0.3, +1.7] 同时满足正向和小幅。下一步沿用表中自上而下首个满足条件的行，按未经四舍五入的区间判定。

| @100 的观察 | 下一步判断 |
| --- | --- |
| L(R − B) > 0 且 L(R − T0) > 0 | 值得在这套配方上做 P 对 R，检验移除当前题的解答后，学生侧预测能保留多少收益。 |
| L(R − B) > 0、L(T0 − B) > 0，且 R − T0 的整个区间落在 [−2, +2] 内 | 能复现蒸馏收益，且只给题目的老师已取得相近提升。若核心问题是提取题目专属知识，优先找参考解答更有增量的设定。 |
| U(R − T0) < 0 | 这套配方下，加入整段参考解答提示降低了学生表现。按基准核对差值与长度分布，再决定是否做 P。 |
| 其余组合 | 如实报告复现未显示明确增益或参考解答作用不确定。保留预定的 @100 结论，@50 仅解释趋势。 |

**解释边界。** R − T0 改动了本题解答及配套措辞，测到的是提供整段参考解答上下文的净效果。即使 R 胜出，也还无法区分本题特有知识和阅读一篇数学解答所诱发的通用行为。只有后续需要区分两者时，再考虑把参考解答换成其他题的解答。

## 5　时间与交付

官方 README 报告 4×H100 训练约 15 分钟，单个检查点评测约 30–50 分钟。四卡串行跑两组的训练量按该速度约半小时，另计下载、环境准备和评测。按单个检查点、单种子评三个基准的 1,080 条回答折算，完整矩阵为 20 份，约需 4×H100 墙钟 10–17 小时。缩减后为 14 份。A100 的排期以本机四卡快报实测更新，同时报告卡型与卡时；三个基准的生成长度可能不同。[官方时间说明](https://github.com/siyan-zhao/OPSD/blob/ae7d2519e94920c4eb6206c0c26de46d9c50abae/README.md)

服务器分两次回报：第一次给 AIME24 三组快报和墙钟时间；第二次给三套基准的逐组逐步成绩、配对差值、题级 95% 判定区间、解码种子标准误、缩减规则是否触发、长度统计、训练和评测各自耗时，并附原始逐题结果及运行配置。官方 AIME24 的 B 51.5%、R@100 57.2% 可作量级参考，正式比较以这次重新评测的 B 为准。

### P@数学（2026-11-24，事后登记）

登记时已见 AIME24 三组快报，B 的 AIME25 批次正在运行，AIME25 和 HMMT25 尚无完整批次。当前批完成后暂停并保留已完成单元。四卡优先完成投影器及 P 的训练。

在初始模型关闭 LoRA、学生非思考无解答提示下取得每个回答位置的 logits s₀ 和最后一层隐状态 r₀。冻结目标为 s₀，只在其 top-64 上加 λ (A r₀)ᵀ(B e_v)，秩为 8，e_v 取 lm_head 的行向量。替代 R 中的带解答老师 logits；沿用 R 的损失、温度、逐元素截断、LoRA、优化器、种子、训练数据流。训练 100 步，每 25 步保存。

投影器从 R 的训练数据流第 3,201 题之后取 1,500 题，各由初始学生按训练采样设置生成一条回答，最多 1,024 tokens。按相同回答前缀计算 R 的带解答思考老师 logits t₀ 及学生 s₀、r₀。在 t₀ top-32 与 s₀ top-32 的并集上，以候选集内学生概率为权重中心化 t₀−s₀，用 Huber 损失拟合。按题四折估计留出误差和全局校准斜率，λ 为该斜率裁至 [0,1]；用所有拟合题重拟合用于训练的投影器。核对固定前缀的目标对 actor 适配器权重不变，以及 λ=0 时等于 s₀。

评测均为种子 1001，沿用 R 的四引擎设置和每题 12 次。P 训练后先评 P@100 的 AIME24；再评 B、R@100、P@100 的 AIME25 和 HMMT25；最后评 T0@100 的 AIME25 和 HMMT25。复用完成的同口径单元。原消息在“主比较”处截断，具体比较和判定规则待用户补全。

**主比较补全（用户随后确认，P 的评测开始前）**：三个基准等权合计，主比较为 P@100 − R@100 和 R@100 − B。每题在 12 次采样上取平均，三组相同题目配对，在每个基准的 30 道题内有放回重抽 10,000 次（seed 20261124），报告点估计和 95% 百分位区间，单位为百分点。其余比较只描述。此补全晚于 B 的 AIME25 单元落盘，早于任何 P 评测；先前登记时间单独保留。

2026-11-25 执行范围更新：P@100 完成 AIME24 快报后，补齐 B、R@100、P@100 的 AIME25 和 HMMT25；复用已完成的 B/AIME25，T0 的两个后续基准暂缓。按三个基准的 P−R 与 R−B 出报告。

### 探索性残差组 Rres（2026-11-25，已见前序结果；先登记再训练）

每一回答前缀在关闭适配器的同一初始模型上求 s₀、r₀、t₀，C=t₀ top-32 与 s₀ top-32 的去重并集。在 C 上从 t₀ 减去 P 的冻结 rank-8 修正 λf(r₀,e_v)，重叠 token 只减一次，C 外 logits 精确保持 t₀。归一化仍用全词表。训练用拟合全部 1,500 题的 P 投影器和原 λ；保留 R 的其余设置、种子 42、100 步。每 25 步保存。

训练前先用 CPU 完成两项诊断。其一，在 1,500 题原四折上用留出投影器、原 λ 和归档的每位置 C，重算残差正 KL 构成，沿用 token_kl 的全词表、分组和温度，另报 <think> 及 C 外正贡献占比；C 外 logits 不变但归一化会影响概率。其二，从三基准归档回答统计 B、R@100、P@100 的汉字出现率，以及逐条回答的汉字数/全部生成字符数的均值，含思考正文。汉字用 Unicode Script=Han，另报同时含汉字和拉丁字母的比例。三项核验完成后训练。

Rres@100 沿用三基准、每题 12 条、种子 1001、4 个 TP=1 引擎。报告准确率、每条平均生成 token 数、Rres−R 的分基准及三个基准等权合计差值和配对题级 95% 百分位区间（各基准内重采样 10,000 次，种子 20261124）。

执行修订：按用户提速请求，训练前的正 KL 诊断可用 GPU。用原始 BF16 路径重算全体 1,500 题，沿用原四折、归档 C、λ 和完整词表，CPU 已有分块单列存档，不混入 GPU 汇总。汉字统计仍使用 CPU。

### MATH-500 轨迹检查与选点（2026-11-25，在 MATH-500 生成任何结果前登记）

等 Rres@100 完成原三个基准后，在 HuggingFaceH4/MATH-500 的 test 集（修订 6e4ed1a2a79af7d8630a6b768ec859cb5af4d3be）上评 B，以及 R、T0、P、Rres 各自 @25/50/75/100，共 17 个状态。在官方 OPSD 评测器中使用 math500 提示和判分，关闭思考模式，温度 0.7，最多 4,096 个新 token，每题 4 条，种子 1001；其余采用官方非思考默认采样配置。四个独立单卡引擎按题号模 4 分题。每个状态报告 2,000 条回答的准确率、平均生成 token 数；标准误以 500 道题为单位，将每题 4 条的正确比例取样本标准差，再除以 √500，单位为百分点。
   
分别在每组四个检查点中选择总答对数最高者；同分取更早步。B 只作参考。等待全部 MATH-500 单元校验完成后冻结选点，再评所选模型在 AIME24、AIME25、HMMT25 上的表现，沿用原思考模式、每题 12 条及种子 1001；已完成且校验通过的同一模型、同一设置的结果复用，缺失单元补跑。MATH-500 用于选点，选点后的表现与原登记 @100 结果分开报告。

### 条件 KL 与取消截断（事后探索，已见前序结果）

单种子 42。R-noclip、R-cond 沿用 R 的数据顺序、固定初始老师（关闭 LoRA、思考且看解答）、非思考学生、温度 1.1、beta=0、全词表、LoRA r64/α128、学习率 5e-6、最多生成 1024 token、100 步和每 25 步保存。两组均禁用逐元素截断。R-noclip 用原老师 q。R-cond 在生成配置所有 EOS ID 与 tokenizer.added_tokens_decoder 全部 ID 的并集 S 中逐 token 保留当前学生概率，启动时记录全部 ID 和字符串。其余 token 按老师在补集的条件分布分配学生的补集质量。学生锚来自 actor 同次前向并 detach。若学生或老师补集概率小于 1e-6，整行取 detach 学生。用 F.kl_div(log_p,log_qstar,reduction="none",log_target=True)，沿用官方掩码和 batchmean。

训练前固定探针在温度 1.1 将原始全词表 KL(q‖p₀) 按链式法则分解。第一种分组为 S 内每个 ID 单独一组、其余一组；第二种为逐元素有符号贡献大于 0.05 和其余。对全部、stop05、actual_eos 分别报告组间 KL 总和 / 全部 KL 总和及组内项，整题重抽 10000 次、种子 20261124。预期第二种整体超过 90%，若如此仅报告、不训练幅度组；第一种整体小、决策位置大。stop05 与 actual_eos 沿用原 EOS 定义。单测要求 S 为空时两臂逐元素损失与梯度一致；随机 logits 梯度为归约系数乘 (p−q*)/1.1，S 内外梯度分别和为零（容差 1e-6）；R-noclip 的逐位置总 KL 非负且等于标准前向 KL。每步含第一步记录损失、未截断原始 KL、学生和老师的 S 质量、保护比例。
