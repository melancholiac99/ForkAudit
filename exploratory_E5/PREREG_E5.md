## 4. 测量（与 M0 同一协议）

- **回放：**
  - 库 1：先抽草稿得到四个替代动作（每批 32 份，最多 300 份），然后每臂 3 次续跑；
  - 库 2：全部可定义点；
  - 库 3–6：只在 Live 点上，每臂每库 3 次；
  - 种子 = `seed_of(...) + 9·10¹² + (b−1)·10¹¹`。
- **标签：**
  - Live：库 1+2 的 30 个结局不全相同；
  - Fork：库 3–6 的五臂似然比 G 检验，p 值由 10,000 次置换给出，α = 0.10；
  - Credit-pivotal：实际动作（12 次）对替代池（48 次）的 Newcombe 90% 区间不含 0；
  - Masked = Fork 且非 Credit-pivotal；
  - 零假设下的期望计数同时报告。
- **一步返回：** 五臂各执行一步。实际动作那一臂必须与原轨迹逐字一致。

## 5. 分层（决定性事实 = 目标商品的 ASIN）

ASIN 匹配不区分大小写，按子串判断。

| 层 | 定义 |
|---|---|
| I（信息受限） | 决策时 prompt 中没有目标 ASIN，且某一臂的一步返回出现了此前历史（初始观察、各步观察与可点击列表）中从未出现过的目标 ASIN |
| U（事实在场） | prompt 中已有目标 ASIN，且至少一臂的返回提及它，且没有臂引入新出现 |
| N | prompt 中没有，任何臂的返回也不提 |
| 其余 | 只报告计数 |

这是保守代理：其他满足全部属性的商品同样可以拿到 reward = 1。

## 12. 修订 1（2026-10-31，运行前）

### 12.1 为什么修订

P5 §3.4 原定的 WebShop 复现目标包括：三域比例与 Masked 份额、内省信号在轨迹内不过 shuffle、信息受限层上策略自身偏好与规则读取的收益。原版 E5 只登记了 W-1 和一个缩窄的 W-2，其余没有登记。这**不是经过论证的取舍，而是设计遗漏**：论文主线转向"信息 × 能力"后，我把确认性检验集中在 W-3 到 W-5，却没有逐项判断旧目标哪些该留。被漏掉的目标大多不需要额外数据（E5 本来就采集），所以没有"为了省成本"的理由。修订在任何 WebShop 数据产生之前提交；W-3 到 W-5 的定义、阈值与核心读法不变。

### 12.2 新增与扩展的检验

**W-0 三域结构**（`analyze`；数据来自 `labels`）
- **W-0a（只报告）：** Dead、Indifferent、Fork、Credit-pivotal ∩ Fork、Masked 占全部可定义点的比例，按任务 cluster bootstrap 的 95% CI，以及零假设期望计数（Fork、Credit-pivotal、Masked）。**不设复现判据**：比例取决于环境与策略（最多 15 步、成功率、可选动作结构都不同），没有理由要求与 ALFWorld 相同。
- **W-0b：** Masked 占 Fork 的份额（Σ Masked / Σ Fork，任务 cluster bootstrap）的 CI 下界 > 0.30。0.30 是描述性阈值，含义是"相当一部分分叉对标量信用不可见"（ALFWorld 为 0.642 [0.592, 0.690]）。同时报告零假设下的份额。
- **W-0c：** 被掩盖分叉上的分样本收益：在库 3–4 上选出最好的替代（并列取最小编号），在库 5–6 上评估它与实际动作的差，任务 cluster CI 下界 > 0。全部 Live 点上的同一量只报告。

**W-2 内省信号**（新增 `introspect` 阶段，GPU；`signals` 阶段，CPU）
- 信号：
  - −conf：在决策 prompt 的生成位置后强制 `<action>`，取实际命令 token 的平均对数概率（M0 臂 A 口径：只取命令 token，不含结束标签与思考）；
  - 采样熵：同原版；
  - 隐状态探针：决策 prompt 最后一个 token（含生成提示）处第 21 层的残差流，用 M0 的 `evalcore.fit_oof_logistic`（按轨迹 GroupKFold 5 折，内层选 C），得到折外分数；第 14、26 层只作描述；
  - W1 目标比特：同原版，只用于分叉边界。
- 边界：
  - 死活（B1）：全部可定义点，标签为 Live，在轨迹内置换（不分进度三分位）；
  - 分叉（B2）：Live 点，标签为 Fork，在轨迹内按进度三分位置换；
  - 置换均为 1,000 次，取 97.5% 分位；AUROC 不按事后方向翻转。
- 预测：
  - **W-2a：** 在 B2 上，−conf、采样熵、第 21 层探针的 AUROC 都不超过各自的 shuffle 97.5% 分位；
  - **W-2b（正对照）：** 在 B2 上，W1 目标比特的 AUROC 超过其 shuffle 97.5% 分位；
  - **W-2c：** 在 B1 上，第 21 层探针的 AUROC 超过其 shuffle 97.5% 分位。

**W-6 信息受限分叉上的策略自身偏好与规则**（`analyze`；数据来自库 1 草稿与 `strata`）
- 人群：全部 I 层 Live Fork 点（不依赖评判者是否打分）。
- 选择分布：
  - 策略：库 1 第一批 32 份草稿中有效且合法的动作，在五臂上计数 + 0.5 后归一化（P4-X 的 X2）；
  - 规则：在一步返回出现目标 ASIN 的臂中均匀选择，若没有则保留实际动作（P4 E1 的世界规则）。
- G_u 用库 1+2 的 q；任务 cluster bootstrap 10,000 次。
- 预测：
  - **W-6a：** 策略的 G_u 的 CI 上界 < 0；
  - **W-6b：** 规则的 G_u 的 CI 下界 > 0；
  - **W-6c：** 规则 − 策略的配对差 CI 下界 > 0。
- 注意："相对候选基线"依赖候选集的构造方式（替代来自草稿中前四个不同的合法动作），报告时与类别解释一起写。

### 12.3 明确排除的检验及理由

| 排除项 | 理由 |
|---|---|
| 手工决策结构特征（B 族） | 需要枚举合法动作集；WebShop 有搜索栏时 `search[...]` 可为任意文本，候选集没有定义 |

| 补自身历史（E2-M 的 M 条件） | ALFWorld 上基本无效（R-M-PARTIAL），不是论文主张 |

## 13. 修订 2（2026-10-31，运行前）：一个预测存在的环境，两个预测缺失的对照

### 13.1 为什么修订

修订 1 之后，E5 仍然只在一个环境（WebShop）上做复现。这样即使全部成立，论文能写的也只是"在第二个环境上又看到一次"，而不能说明效应**只**出现在信息受限的分叉上。再加上 WebShop 自身的三个风险：决定性事实只能用目标 ASIN 作代理（其他满足属性的商品同样能拿到 reward = 1，第 5 节）；7B 在 WebShop 上成功率低，Dead 点可能占多数，I 层数量没有把握；环境搭建最重。

修订 2 改成"预测存在 + 预测缺失"的设计：
- **E5-S（检索 Agent，开放检索）**：决定性事实是多跳问题的两篇支撑文章，必须检索才能拿到，预测效应**存在**；
- **E5-C（同一批问题，上下文给全）**：同一 Agent、同一问题、同一预算，只是任务描述里直接给出十段上下文（含两篇支撑文章），预测反馈效应**缺失**——环境内对照；
- **E5-K（Sokoban）**：完全可观察，决定性信息始终在 prompt 中，难点在计算而不在信息，预测反馈效应**缺失**——跨环境对照，同时检验"信息还是计算"。

如果 E5-S 上 F − S 为正、而 E5-C 与 E5-K 上 F − S 接近零，并且两者之差显著（A-3、K-3），结论就从"复现"升级为跨环境的双重分离：一步反馈的价值专属于信息受限的分叉。

本修订在 E5 的任何数据（任何环境的 rollout、回放、试点）产生之前提交。第 4 节的测量协议、第 7 节的评判协议、W-0 到 W-6 的定义与阈值、核心读法与结构读法都不变，只是把适用环境从 WebShop 换成 E5-S。

| 替代动作 | 库 1 草稿中前四个不同的有效动作（K = 5 臂，同第 4 节） | 同 E5-S | 其余三个方向（K = 4 臂）；实际动作为原地不动的点记为未定义并计数；库 1 仍抽一批 32 份草稿，用于采样熵与策略边际 |
| 决定性事实 | 两篇支撑文章的标题 | 同 E5-S（按构造全部在 prompt 中） | 无隐藏事实；规则 = 在 prompt 棋盘上做 BFS 的规划器 |

模板文件 `prompts/search_template*.txt`、`prompts/sokoban_template*.txt` 从上述 commit 逐字复制（只去掉首尾换行，与 `common.load_template` 一致）。

**已声明的偏离（DECISIONS D-061）：**
- 检索出错时中止运行，而不是像 verl-agent 那样把错误文本给 Agent 看；
- 每个查询第一次检索到的文档写入共享缓存（SQLite，所有进程、所有阶段、E5-S 与 E5-C 共用，先写者为准），保证回放逐字一致，即使检索服务不是逐位确定的；
- Sokoban 生成失败时 verl-agent 用 `abs(hash(str(seed)))` 重试，而 Python 的字符串哈希按进程随机；这里改为 `seed + 1,000,003 × 尝试次数`，并记录实际使用的种子。房间在冻结时一次生成并存档，回放从不重新生成。

**分层（E5-S）**，沿用第 5 节的定义，把"目标 ASIN"换成"两篇支撑文章的标题"（规范化后按标题匹配 prompt 与各臂一步返回中 `<information>` 块里的文档）：
- I：prompt 中至少缺一篇支撑文章，且某一臂的一步返回检索到一篇缺失的、历史中从未出现过的支撑文章；
- U：两篇支撑文章都已在 prompt 中；
- N：缺支撑文章，且没有任何臂检索到缺失的支撑文章；
- 其余：只报告计数。

代理的局限：wiki-18 按百字分段，标题在场不等于支撑句在场；问题也可能凭参数知识答对。

### 13.3 预测

**E5-S（预测存在）：** W-0 到 W-6 与核心读法、结构读法（第 8、12 节）原样适用，WebShop 换成 E5-S。W1 目标比特（W-2b）与 W-6 的规则改为"该臂的一步返回检索到缺失的支撑文章"。功效门不变（I、U 层各 ≥ 40 个有评判分数的 Fork）。

**E5-C 与 E5-K（预测缺失）**，人群为全部有评判分数的 Live Fork（按构造都在 U 层）：
- **A-1：** 32B 的 F − S 的 CI 上界 < 10 pp。（ALFWorld I 层 32B 的 F − S 为 +50.8 pp，10 pp 约为其五分之一。）
- **A-2：** S 条件下 32B − 7B 的 CI 下界 > 0（事实在场时，能力起作用）。
- **操纵检查：**
  - C-0（E5-C）：Live 可定义点中 ≥ 95% 落在 U 层；
  - K-0（E5-K）：规划器规则的 G_u 的 CI 下界 > 0。规划器只用 prompt 中的棋盘与剩余步数，选能开始一条最短解的臂；成立说明"选对所需的信息就在 prompt 中"。
- **功效门：** ≥ 40 个有评判分数的 Live Fork。
- **读法（每个环境单独，按序取第一个满足者）：** **R-ABS-CONTROL-FAILED**（操纵检查不成立）→ **R-ABS-UNDERPOWERED** → **R-ABS-CONFIRMED**（A-1 与 A-2 都成立）→ **R-ABS-PARTIAL**。
- W-0、W-1、W-2 的数值照样计算，只描述、不判定。

**跨环境对比**（`e5_run.py cross`）：
- **A-3：** E5-S I 层 Fork 上 32B 的 F − S，减去 E5-C Fork 上的同一量，CI 下界 > 0。两者来自同一问题池，按问题联合重抽样。
- **K-3：** E5-S I 层 Fork 上 32B 的 F − S，减去 E5-K Fork 上的同一量，CI 下界 > 0；两样本独立重抽样。

**只报告的描述项（E5-S、E5-C）：** 各层 Fork 上答案臂的比例，以及五个一步返回完全相同的 Fork 的比例。查询不同但检索结果相同的臂在检索环境中不可避免；A-3 的差异若与臂的构成同时变化，须在正文中说明。

### 13.4 试点门（不读任何 Fork 标签与评判输出）

- **试点集：** E5-S / E5-C 用同一组 50 个试点问题；E5-K 每个难度级 50 个试点房间。试点数据不进入任何分析。
- **阶段：** rollout、库 1、库 2、peek、labels（只用 Live）、strata、`pilot`。
- **通过条件：**
  - 7B 成功率在 [0.15, 0.85] 内；
  - Live 点占可定义点 ≥ 0.25；
  - 确定性：重放分歧为 0，且实际臂的一步返回与原轨迹逐字一致（100%）；
  - 按正式集规模外推：E5-S 的 Live I 与 Live U 各 ≥ 150；E5-C、E5-K 的 Live ≥ 300。
- **未通过时（规则在此写定，执行前写入 DECISIONS）：**
  - E5-S 只有外推数量不够：正式集扩大一次，取满足外推的最小 500 的倍数（上限 2,000 题），E5-C 同步扩大；
  - E5-S 的成功率、Live 比例或确定性不通过：E5-S 失败，记录；改按第 1–12 节在 WebShop 上运行（WebShop 同样先过本节的试点门）；
  - E5-C 不通过：放弃环境内对照，A-3 不检验，记录；
  - E5-K 按第 13.5 节的难度阶梯处理。

### 13.5 Sokoban 难度阶梯

L1 为 verl-agent 默认设置（6×6、1 个箱子、反向搜索深度 30、最多 15 步）；L2、L3 只把反向搜索深度降为 15、6（箱子离目标更近），其他不变。按 L1 → L2 → L3 依次试点，取第一个通过第 13.4 节全部条件的级别冻结正式集。L1 成功率 > 0.85，或三级都不通过，则放弃 E5-K（K-3 不检验），记录。

### 13.6 合并读法与论文结论的约束

**合并读法：**
- **R-E5-DISSOCIATION：** E5-S 的核心读法为 R-E5-REPLICATE，且至少一个缺失环境为 R-ABS-CONFIRMED、其跨环境对比（A-3 或 K-3）成立；
- **R-E5-PRESENCE-ONLY：** E5-S 为 R-E5-REPLICATE，但没有缺失环境同时满足上述条件；
- 其他组合逐项报告，不另起名字。

| 结果 | 可以写 | 不能写 |
|---|---|---|
| R-E5-DISSOCIATION | 一步反馈的价值专属于信息受限分叉，在检索环境与 ALFWorld 上成立，并在事实在场的对照中消失 | 对所有 Agent 环境普遍成立 |
| E5-C 的 A-1 不成立 | 必须写明：上下文已给全时一步反馈仍有价值，"信息而非能力"的表述须收窄 | 把 E5-S 的效应解释为纯信息效应 |
| E5-K 的 A-1 不成立、E5-C 成立 | 在 Sokoban 上一步反馈也有价值（替评判者完成了计算）；"信息"结论限于需要检索事实的分叉 | 一步反馈只提供信息 |
| A-2 不成立 | 能力效应只写 ALFWorld | 能力在事实在场时总是起作用 |
| 操纵检查不成立 | 该对照无效，不用于任何结论 | 用它支持或反对主张 |
| 任何结果 | 结构读法的约束照第 12.5 节，适用于 E5-S | — |
